# Glossary

**Purpose:** plain-English definitions of every term used across the docs.

Last updated: 2026-10-08

| Term | Meaning |
|---|---|
| ADR | Architecture decision record: a short document recording one decision, why, the alternatives, and when to reconsider. See [adr/README.md](adr/README.md). |
| Agent | A step (or loop of steps) that does a task, possibly using an LLM. In LangGraph each agent is a node. |
| Alembic | The tool that records every database table change as a migration file in Git. |
| API Gateway | A front door that routes and protects APIs. Here Nginx plus FastAPI authentication fills this role. |
| at-least-once | A delivery guarantee: the message is delivered one or more times, never zero. Needs idempotency to avoid duplicates. |
| AWQ / GPTQ | Two common formats of pre-quantised (shrunk) model weights found on Hugging Face. |
| Box | The document store where RCA Word files live. It stays the store of record. |
| chunk | A piece of text small enough to retrieve precisely. |
| circuit breaker | A guard that stops calling a failing service for a cool-down, then probes it before resuming. States: closed, open, half-open. |
| CI | Continuous integration: automatic checks on every change. CD is continuous delivery/deployment. |
| cluster | A group of incidents with the same root cause. |
| continuous batching | vLLM's technique of merging tokens from many requests into shared GPU passes. |
| edge | A path between nodes in a LangGraph graph. |
| egress / ingress | Traffic going out of our system (to ServiceNow, Box) / into it (from browsers). |
| embedding | A list of numbers that represents the meaning of text; similar text gives similar numbers. |
| engine (SQLAlchemy) | A connection pool: open "phone lines" to the database, reused for speed. |
| eventual consistency | Data becomes up to date after a short delay (30-60 s here) rather than instantly. |
| evals | A fixed set of questions with known answers used to measure AI accuracy. |
| fine-tuning | Training a model further to change its behaviour. Not used here ([ADR 0009](adr/0009-rag-over-fine-tuning.md)). |
| human-in-the-loop | A person must review and approve before an action happens (every RCA, [ADR 0012](adr/0012-human-review.md)). |
| idempotency | Doing an operation twice has the same effect as once, so retries are safe. |
| incident | A ServiceNow ticket for a problem. |
| KV cache | A model's working memory for each request; grows with concurrent requests and context length. |
| LangGraph | The library that models the Advisor agent as a graph of nodes with shared state. |
| LLM | Large language model. |
| leaky bucket / token bucket / fixed window / sliding window | Rate limiting algorithms; see [rate-limiting.md](architecture/rate-limiting.md). |
| migration | A file describing one change to the database schema. |
| modular monolith | One deployable application with clean internal modules, instead of many services. |
| node | A function (an agent or step) in a LangGraph graph. |
| Nginx | The web server in front of the app: HTTPS, routing, rate limiting. |
| OpenAPI | A machine-readable description of an API, generated by FastAPI. |
| OpenTelemetry | A standard for tracing a request across services. |
| Ollama | A tool for running models locally; used on laptops. |
| pgvector | A PostgreSQL extension that stores and searches vectors. |
| Pydantic | A Python library for validating data shapes; used for API schemas, LLM structured output and settings. |
| quantisation | Shrinking a model by storing numbers with fewer bits (for example 4-bit) so it fits in less GPU memory. |
| RAG | Retrieval-augmented generation: fetch relevant text first, give it to the model, and have it answer using that text. |
| RCA | Root cause analysis: the report explaining why an incident happened. |
| session (SQLAlchemy) | One unit of work with the database: open, do the work, commit, close. |
| SNOW | ServiceNow. |
| SQLAlchemy | The Python library that translates classes and objects into SQL. |
| SSE | Server-Sent Events: an HTTP response the server keeps open and keeps writing to. |
| staging | A test environment that mirrors production, where changes are tried first. |
| state (LangGraph) | The shared whiteboard that moves from node to node. |
| vector | A list of numbers; here the embedding of a chunk. |
| vLLM | A server for running LLMs on GPUs with high concurrency and an OpenAI-compatible API. |
| VM | Virtual machine allocated by the IT infrastructure team. |
| WebSocket | A persistent two-way connection between browser and server. |
| walking skeleton | A tiny end-to-end version of the whole system, built and deployed first (`docs/build-plan.md`). |
| worker | A separate process that runs background jobs from a queue. |
